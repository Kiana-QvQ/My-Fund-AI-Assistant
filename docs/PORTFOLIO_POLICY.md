# 保守进阶型指数定投组合 README

## 一、方案概述
本组合面向**风险偏好保守、追求长期稳健增值**的投资者，以「A 股宽基为核心、美股小仓位分散、短债资产做安全垫」为核心架构，通过定投方式平滑成本，配合估值分位规则优化买入节奏，在控制最大回撤的前提下获取市场长期平均收益。

组合以跑赢居民消费价格指数（CPI）通胀为基础保值目标，长期力争向广义货币供应量（M2）增速靠拢，在低波动前提下实现资产稳健增值。近5年国内CPI年均通胀率约1.8%，M2年均增速约8.2%，本组合长期收益可稳定覆盖通胀，权益行情较好阶段可接近M2增速水平。

- **组合定位**：稳健增值型，权益与固收均衡配置
- **建议持有周期**：3 年以上
- **预期年化收益**：长期 3.2%~7.6%（随市场周期波动）
- **历史最大回撤参考**：约 -18%（高点入场 5 年维度）

---

## 二、核心投资理念
1. **A 股为主，美股为辅**：沪深 300 + 中证 500 构成权益主力，押注国内经济长期增长；标普 500 + 纳斯达克 100 小仓位配置，分散单一市场风险，赚取全球龙头企业盈利增长收益。
2. **固收打底，控制波动**：短债类资产作为组合压舱石，大幅降低账户整体回撤，提升持有体验，避免因短期波动中断定投。
3. **低估买入，高估暂停**：以指数估值历史分位为锚，只在偏低估区间定投加仓，中等估值以上停止新增投入，避免高位无脑接盘。
4. **长期持有，定期再平衡**：不博弈短期行情，依靠企业盈利增长和估值周期赚钱；每年校准一次仓位比例，维持风险收益结构稳定。

## 五、场内 vs 场外：区别与费用全拆解
### 1. 基础定义
- **场内**：在证券交易所挂牌交易，需开通证券账户，像股票一样实时买卖，价格全天波动。ETF 均为场内品种。
- **场外**：在交易所外的基金销售渠道申购赎回，全天只有一个收盘净值，按金额申购、按份额赎回。ETF 联接基金属于场外品种。

### 2. 核心区别对比
|对比维度|场内 ETF|场外联接基金（A 类）|
|---|---|---|
|交易渠道|证券账户|第三方基金平台、银行、基金公司官网|
|成交价格|全天实时报价，每秒波动|每日 1 个收盘净值，15:00 前下单按当日净值|
|最低买入门槛|1 手 = 100 份，必须 100 份整数倍|通常 10 元起，可精确到分|
|到账速度|卖出资金当日可用，次日可取|赎回到账 T+1~T+4，QDII 为 T+7+|
|自动定投|需通过条件单实现，受门槛限制|原生支持自动扣款定投，比例精准|

### 3. 费用完整明细
#### 共同费用：年运作费（管理费 + 托管费）
所有渠道一致，每日从基金净值中自动扣除，投资者无需额外支付，看到的净值已扣除此项费用。

#### 场内交易费用
|费用项|收费规则说明|
|---|---|
|交易佣金|按成交金额比例收取，普遍万 0.5~ 万 1；多数券商默认**单笔最低 5 元**（买卖双向收取）；部分券商针对场内基金可申请取消最低限制|
|过户费|沪市品种收取十万分之 0.2，双向，金额极低可忽略|
|印花税|ETF 免征|
|隐性成本|1. 100 份门槛导致小额资金闲置；2. QDII 品种存在溢价损耗（市价高于净值）；3. 买卖滑点|

#### 场外交易费用（A 类份额，长期持有首选）
|费用项|收费规则说明|
|---|---|
|申购费|原费率 1.2%，第三方平台普遍 1 折，实际约 **0.12%**，买入时一次性扣除|
|赎回费|持有时间越长越低；持有 ≥ 2 年通常全额免除；持有不满 7 天收取 1.5% 惩罚性费用|
|销售服务费|A 类无，C 类按年计提（短期持有选 C 类）|
|隐性成本|几乎无溢价损耗；QDII 存在少量换汇摩擦成本，已体现在净值中|

### 4. 成本适用场景结论
- **每月定投金额 ≤ 500 元**：场外方案综合成本更低，无门槛限制，可精准执行比例，推荐场外
- **每月定投金额 ≥ 2000 元**：单笔金额覆盖最低佣金门槛后，场内 ETF 综合成本更低，推荐场内
- **大额一次性买入**：场内 ETF 费率优势明显，优先选择场内

## 六、定投执行策略
### 1. 初始建仓规则
- 初始本金建议分 **6 个月分批建仓**，平滑入场成本，避免一次性买在高位
- 第 1 个月投入总建仓资金的 20%，第 2~6 个月每月投入剩余资金的 16%
- 资金严格按 51% / 27% / 11% / 8% / 3% 的目标仓位比例分配至各标的

以初始本金 10000 元为例：
|建仓阶段|当月总投入|短债底仓（51%）|沪深300（27%）|中证500（11%）|标普500（8%）|纳指100（3%）|
|---|---|---|---|---|---|---|
|第1个月|2000元|1020元|540元|220元|160元|60元|
|第2~6个月（每月）|1600元|816元|432元|176元|128元|48元|

### 2. 每月持续定投（现行口径：每交易日自动扣款）

> **2026-10-15 起口径变更**：四只持仓标的全部改为招商银行 App「每交易日」自动定投，**不再按 51/27/11/8/3 的月度预算比例手动申购**。

|标的|场外|每交易日|月终止金额|扣款日历|
|---|---|---|---|---|
|嘉实超短债债券 A|`012773`|5 元|不设|A 股交易日|
|华泰柏瑞沪深300ETF联接 A|`460300`|5 元|不设|A 股交易日|
|南方中证500ETF联接 (LOF) A|`160119`|5 元|不设|A 股交易日|
|南方纳斯达克100指数发起（QDII）A|`016452`|10 元|不设|A 股交易日（QDII 确认净值可能再顺延）|
|博时标普500ETF联接 (QDII) A|`050025`|未设置|—|仅估值观察|

- 每交易日合计 **25 元**；非交易日顺延至下一交易日（见 [`TRADING_CALENDAR.md`](TRADING_CALENDAR.md)）。
- 月度实际扣款取决于当月交易日数（2026 年全年 242 个交易日，单月 14～23 天 → 约 350～575 元），**没有月度上限**。
- 这笔钱**不计入**组合「规划」预算（`dca.personal_schedules` 语义），也不占用建仓本金 ¥10,000 的额度口径。
- 每年交易日数差异带来的金额波动属于设计内，不做人为抹平。

### 3. 场内「蓄水池」执行方案（解决 100 份门槛问题）
由于场内 ETF 最低 100 份买入，小额定投无法直接拆分至每只标的，采用以下机制：
1. 每月定投资金全部买入短融 ETF（或证券账户闲置理财），作为资金蓄水池
2. 当对应指数估值达标、且蓄水池资金足够买入 1 手对应 ETF 时，再调拨资金买入
3. 长期维持 51/27/11/8/3 的目标仓位比例，每年做一次再平衡校准

## 七、买入与估值执行策略
本策略以指数近10年 PE-TTM 历史分位为核心锚点。**每日自动定投**由银行按交易日扣款，系统只输出「维持 / 建议暂停 / 建议加码」的**监控结论**；**建仓**另以近1年分位 + 回撤分档独立触发，与定投邮件分离。原「组合定投预算（月基础 300 / 封顶 1000）」代码路径保留但已停用。

### 核心原则（定稿）
1. **定投监控邮件**与**建仓邮件**完全独立，不合并、不混淆  
2. 每日定投：银行每交易日自动扣款，**无需手动申购**；系统只提示是否建议暂停/加码  
3. 监控周报：**每周四约 12:00 CST** 汇总每日定投进度与档位结论  
4. 建仓：仅状态变更时单独推送  
5. 工作日监测档位/倍率/暂停变更；有变更即发事件信  
6. 工资日资金留存，无单独工资日邮件  

### 每日自动定投监控（现行）
| 项 | 值 |
|---|---|
| 扣款方 | 招商银行 App，每交易日自动扣款 |
| 每交易日合计 | **25 元**（短债 5 / 沪深300 5 / 中证500 5 / 纳指100 10） |
| 月终止金额 | **不设**（`monthly_stop_amount: null`） |
| 组合周度预算 | **已停用**（`dca.portfolio_weekly_enabled: false`），weekly/monthly 恒为 0 |
| 档位口径（A股/美股同一套） | ＜40%→300%（可考虑加码）；40%～50%→200%；50%～60%→150%；60%～70%→100%（维持）；70%～80%→70%；80%～90%→50%（维持不加码）；**≥90%→建议暂停**。分位＜60% 但回撤＜1% 或缺回撤数据时**不建议加码**，维持 100% |
| 监控邮件 | 周四周报 + 事件信；`dca.email.max_dca_emails_per_month` 默认 **6** |

**QDII溢价滞回**：缺失或＞2% 建议暂停；≤1% 才建议恢复；1%～2% 继续观望（fail-closed）。能否扣款还须场外 **开放申购/限大额**、金额≤日限额且≥购买起点。近52周高点（回撤＜1%）或缺回撤数据：**不建议加码**，维持 100%。

#### 已停用的组合周度预算（保留代码路径）

`scripts/investment_plan.py::allocate_dca_plan` 仍保留原「组合月基础 300 / 封顶 1000、按 `target_allocation` 权重分配、本周金额 = 本月剩余预算 ÷ 本月剩余周四」的实现，但政策里 `portfolio_weekly_enabled: false` 会把 `base`/`cap` 置零，使其只输出档位信号而不输出申购金额。要恢复旧口径，把该开关改回 `true`。

### 每日自动定投设置（四只标的）

四只标的的 schedule 都写在 `config/portfolio_policy.json` 的 `dca.personal_schedules`：

| 字段 | 含义 |
|---|---|
| `schedule` | `trading_day` = 每交易日 |
| `market` | `a_share` / `qdii_us`，决定扣款日历与溢价的适用性 |
| `valuation` | `pe_10y`（按十年分位监控）/ `none`（短债，不看 PE） |
| `index` | 关联的指数名（短债为 `null`） |
| `trading_days_only` | `true` = 仅交易日扣款，非交易日顺延 |
| `daily_amount` | 每交易日金额 |
| `monthly_stop_amount` | `null` / `0` = **不限额度**；正数 = 当月累计达到后停止 |
| `reconciled_through` | 该日**及以前**已按招行 App 截图人工对账，不再自动补记 |
| `effective_from` | 自动记账起始日；缺省时取 `reconciled_through` 的**次日**。此前的日期不会被自动补记 |
| `enabled` / `auto_ledger` | 关闭后系统不再补记 |

记账：A 股交易日的 GitHub Actions 会运行 `scripts/sync_personal_dca.py`，按缺漏交易日自动写入账本（幂等，`purpose=dca`）。要补人工确认过的历史区间，用 `--since YYYY-MM-DD --fund <代码>`。

### 权益持仓均价（沪深300 / 中证500 / 纳指）

- 用成交日历史净值估算每笔份额，汇总后得到持仓均价；看板展示「相对均价」涨跌幅。
- 建仓：现价相对均价 ≥8% 开始软降建议金额，15% 降至 50%；不替代估值主信号。
- 四只每日自动定投不受均价软降影响——金额由银行固定，系统只提示是否建议暂停/加码。
- 可用 `scripts/backfill_equity_shares.py --align <代码> <份额>` 按券商持仓校准；之后买入尽量带 `--shares/--nav`。

### 建仓（独立事件 · 状态机）

状态：`不可买` / `宽松观测仓 25%` / `正式小额底仓 50%` / `正式建仓 100%` / `QDII溢价阻断` / `止盈观察`（另有瞬时风险态 `数据源失败`）。

- **每日约 12:00 CST** 刷新真实 PE、回撤、溢价与状态；**不**再跑 21:00
- 邮件仅在**状态变化**时发送；买入金额、距目标进度变化、未买满**不**催促
- 升级/恢复：连续 **2 个交易日**确认后发送
- 立即发送：QDII溢价＞2%、建仓条件失效、止盈观察、数据源失败
- 状态持久化字段：`current_state` / `candidate_state` / `candidate_count` / `last_notified_state` / `last_notified_at`
- 不与周报合并；记账用 `purpose=build`（定投用 `purpose=dca`）

> 短债 `012773` 不看 PE/回撤。场外未知价：估值日 ≠ 净值确认日属正常。

定投能降低一次性择时压力，但不能保证盈利或避免亏损；本规则是择时过滤器，不是完整买卖系统。

### 实操时点与邮件提醒（招商银行场外）

场外是「未知价」申购：**估值信号日 ≠ 申购净值确认日** 属于正常现象。每日定投由银行自动扣款，**不需要手动下单**。

| 时间（约 CST） | 系统 | 邮件 |
|---|---|---|
| **每交易日** | 银行自动扣款；工作流运行 `sync_personal_dca.py` 补记账本 | — |
| **每周四约 12:00 CST**（A股交易日） | 刷新估值 + **每日定投监控周报** | 各标的档位/结论、本月已记笔数与金额；若建议暂停会点名 |
| **其他工作日约 12:00 CST** | 刷新 + 状态机 | 定投档位/结论变更 → 定投事件信；建仓状态变更 → **建仓事件信（独立）** |
| **A股休市日** | 刷新美股估值 + README | 不扣款（顺延）；可发建仓/风险事件信；**不发**监控周报；周四休市则周报顺延下一交易日 |
| **21:00** | 不运行 | — |

交易日判定规则见 [`TRADING_CALENDAR.md`](TRADING_CALENDAR.md)：周一至周五剔除法定节假日；日历不可用时**跳过并在下次运行重算**（fail-closed）。

#### 操作后记账（人工确认）
定投由银行自动执行，正常无需手动报账；只有**手动买入/止盈**或**人工确认过的历史补账**才需要：

```bash
# 手动补记定投（含历史区间，需人工核对）
python scripts/sync_personal_dca.py --since 2026-08-20 --fund 016452 --dry-run
python scripts/record_holding.py buy --fund 460300 --amount <金额> --purpose dca --note "定投"
# 建仓
python scripts/record_holding.py buy --fund 460300 --amount <金额> --purpose build --note "建仓"
```

`purpose=dca` / 备注含「定投」的买入会计入账本定投流水；建仓请用 `purpose=build`，以免混入定投口径。四只标的的每日定投不计入组合周度预算（该预算已停用）。

#### 发送条件（摘要）
- 每日定投监控周报：每周四（A股交易日）固定发送；若周四休市，顺延至其后第一个 A 股交易日补发  
- 定投事件：档位/结论（维持↔建议暂停↔可考虑加码）变更时发送（**与周报可同日并存**）；本月已记金额变化**不**触发邮件  
- 建仓事件：状态机确认后的状态变化才发送（升级需 2 日；风险立即）  
- Secrets：`ALERT_EMAIL`、`SMTP_USER`、`SMTP_PASS`；可选 `SMTP_HOST`/`SMTP_PORT`/`MAIL_FROM`

## 八、再平衡规则
1. **再平衡周期**：每年 1 次，固定在年末或年中执行
2. **触发条件**：任意一类资产偏离目标仓位比例 ±5% 以上
3. **操作方式**：卖出超配部分，买入低配部分，回归目标仓位；定投阶段也可通过调整每月定投分配比例，逐步回归目标，减少交易摩擦

---

## 九、风险提示
1. **市场波动风险**：权益类资产短期波动较大，熊市阶段可能出现 18% 左右账面浮亏，属正常现象，需做好资金规划，用长期不用的闲钱投资
2. **汇率风险**：美股 QDII 资产以美元计价，人民币大幅升值会侵蚀人民币口径收益；小仓位配置下对整体组合影响有限
3. **QDII 额度风险**：外汇额度紧张时，场外 QDII 基金可能限购，场内 QDII-ETF 可能出现高溢价
4. **信用风险**：短债资产底层为高评级债券，违约概率极低，但非刚性兑付，极端市场环境下可能出现短暂小幅回撤
5. **历史业绩不代表未来**：所有回测数据仅为历史模拟，不构成收益承诺

## 十一、AI 规划与交易日记项目结构

本项目采用“上游项目只读、本项目编排层独立”的方式接入 AI，避免修改或破坏
GitHub 拉取的第三方项目。

```text
integrations/
  upstream/                 第三方项目的只读副本
    ai-berkshire/
    vibe-trading/
  adapters/                 我们自己的适配器，不放入上游目录
app/
  ai_assistant.py           规划、日记和复盘入口
config/
  portfolio_policy.json     可供程序读取的投资政策
journal/                    个人交易日记
reports/                    AI 生成的报告
data/                       行情、估值和账户导出数据
logs/                       本地运行日志
docs/AI_INTEGRATION.md      AI 接入边界和分阶段方案
```

### AI 的职责边界

- `plan`：根据投资政策和最新观察生成定投/再平衡建议
- `journal`：把交易事实、判断、情绪和结果整理成日记草稿
- `review`：检查交易是否偏离 README 中的仓位和估值规则
- 默认只提供建议和草稿，不自动下单，必须人工确认

### 本地运行

先配置 `config/.env.example` 中的 AI 服务环境变量，然后运行：

```powershell
python app/ai_assistant.py --mode plan --input "本月可投入300元，510300估值分位32%，当前短债53%"
python app/ai_assistant.py --mode journal --input journal/daily/2026-07-16-template.md
python app/ai_assistant.py --mode review --input reports/latest-trade.md
```

第三方项目的更新、依赖安装和运行都应在各自的
`integrations/upstream/<项目名>` 目录内进行；不要直接修改这些目录中的文件。
